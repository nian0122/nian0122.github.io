Django、Docker、K3s 和 GitHub Actions 学习笔记

Nianer 发布于 2026-11-19

  • 🏷️ Docker
  • 🏷️ 部署

这次我从 Django 项目结构和 Python 配置入手，先在 Windows 上运行项目，再用 Docker Compose 接入 PostgreSQL，最后把构建和发布流程搬进 GitHub Actions。教程使用 DigitalOcean Registry 和托管 Kubernetes，我改用了 GHCR、云服务器上的 K3s 和集群内 PostgreSQL。

1. Django 与 Python 基础

  • Django 的项目配置集中在 settings.py，urls.py 负责请求路由，视图处理请求，models.py 定义 ORM 模型。可以分别类比 Spring Boot 的应用配置、Controller 路由和实体映射。
  • 在 web 目录运行 django-admin startproject django_k8s .，会直接在当前目录生成 manage.py，并创建 django_k8s 配置包。最后的点表示当前目录。
  • dir(obj) 列出名称，help(obj) 查看说明，inspect.signature(func) 查看普通 Python 函数的参数。读包时先看文档和最小示例，再沿实际调用找源码。
  • __file__ 是当前模块的文件路径。比如查看 django_k8s.__file__，常得到包的 __init__.py。在 settings.py 中，Path(__file__).resolve().parent 是配置文件所在目录，再向上一层是 web。
  • __dict__ 保存许多对象的属性，__init__ 在实例创建后初始化它。obj.__bool__ 取到方法对象，obj.__bool__() 执行它，通常直接用 bool(obj)。read_dotenv() 返回 None 时，bool(None) 为 False，不能拿这个返回值判断加载是否成功。
  • 教程中的 dotenv.read_dotenv(str(ENV_FILE_PATH)) 把文件里的键值读进当前进程环境。settings.ENV_FILE_PATH 能读到定义在 Django settings 模块里的同名大写配置。定义在 wsgi.py 的变量属于那个模块。
  • SECRET_KEY 用于 Django 的加密签名，例如密码重置令牌和签名后的数据。长期部署应保管原有密钥。
  • DEBUG=False 关闭调试异常页，需要配置 ALLOWED_HOSTS。本项目从 ENV_ALLOWED_HOST 读取域名。HTTP 400 可以去日志里查 DisallowedHost。域名解析到服务器之后，还要经过端口、Kubernetes Service 和 Django 路由。

2. 本地运行、迁移和静态文件

在 web 目录并激活 Windows 虚拟环境后执行：

python -m pip install -r .\requirements.txt
python .\manage.py migrate
python .\manage.py createsuperuser
python .\manage.py runserver
  • migrate 更新数据库结构。No migrations to apply 表示当前连接的数据库已完成迁移。管理员通过 createsuperuser 或部署里的 migrate.sh 创建。若 Admin 登录失败，检查连接的数据库是否与创建用户时相同，以及账号是否启用并具备 staff 身份。
  • 进入 Django shell 后执行 from django.db import connection; print(connection.vendor) 可确认后端是 postgresql 还是 sqlite。开发机和容器各有自己的环境变量。这次 PostgreSQL 已通过健康检查，Django 却仍在使用 SQLite。项目要等全部 PostgreSQL 连接配置都有值才会切换后端，所以还需要检查 Django 进程读到的配置。
  • Windows 虚拟环境的命令位于 venv\Scripts。容器中的虚拟环境在 /opt/venv，可直接用 /opt/venv/bin/python。dash 里激活脚本用 . /opt/venv/bin/activate，Bash 也支持 source。Gunicorn 在 Linux 容器里运行，应用入口写作 django_k8s.wsgi:application。
  • ModuleNotFoundError: No module named 'whitenoise' 表示启动进程所用的 Python 环境缺包。collectstatic --noinput 将静态资源复制到 STATIC_ROOT，本项目由 WhiteNoise 提供静态文件。Gunicorn 下曾出现登录页返回 200、Admin 的 CSS 和 JavaScript 返回 404 的情况。配置 STATIC_ROOT 和 WhiteNoise，并在启动前收集静态文件后，抽查的五个资源都返回了 200。No directory at ...\staticfiles 时可以运行 collectstatic。HTTP 304 表示浏览器可继续用缓存。
  • Admin 请求中，/admin 常返回 301 补斜线，/admin/ 在未登录时返回 302 跳到登录页。登录表单提交返回 200 仍可能是页面重新显示了错误。本会话曾验证域名 HTTP 的 /admin/login/ 返回 200，而根路径 / 返回 404。
  • PostgreSQL 的 libpq 参数用 sslmode=require。本项目集群内的 PostgreSQL 未启用 TLS 时，可以设 DB_IGNORE_SSL=true。要确认生效，检查运行中的容器和 Django 的实际配置。

3. Docker Compose 与 GHCR

  • Compose 的 env_file 把键值注入容器进程。Django 用数据库端口变量连接 PostgreSQL，PostgreSQL 自己的监听端口由它读取的参数或配置决定。
  • command: -p 5434 让 PostgreSQL 进程监听 5434。expose: [5434] 声明容器端口，不做宿主机发布。ports: ["5434:5434"] 将宿主机 5434 发布到容器 5434。也可以用 "5434:5432" 映射到 PostgreSQL 的默认容器端口。同一个 Compose 网络内的 Django 可以用服务名与容器端口访问数据库。
  • 服务引用 staticfiles 命名卷时，在 Compose 顶层 volumes 声明它。version 过时的提示可以独立处理。
  • PostgreSQL 18 官方镜像建议把持久卷挂到 /var/lib/postgresql。已有旧版数据目录时先确认版本并安排数据迁移，改挂载路径本身不会升级数据库格式。
  • Docker 构建的最后一个参数是上下文。从 web 目录使用 docker build -f Dockerfile -t ghcr.io/nian0122/django-k8s-web:v1 .。PowerShell 多行用反引号续行，Bash 才用反斜线。Dockerfile 的 COPY 路径以构建上下文为基准。
  • 单标签推送写 docker push ghcr.io/nian0122/django-k8s-web:v1，推全部标签时把标签去掉，再加 --all-tags。上传超时可以重试，已上传的镜像层通常会被复用。出现 denied 或 403 时检查凭据和镜像包权限。

4. K3s 配置和日常排错

  • kubeconfig 包含 API 地址、信任的 CA、认证信息和 context。PowerShell 用 $env:KUBECONFIG = "$HOME\.kube\k3s-remote.yaml" 设置当前进程的配置路径。也可以每次传 --kubeconfig。环境变量为空时，kubectl 默认读取 $HOME\.kube\config。VS Code workspace 里的设置是否进入终端取决于配置项和终端的启动方式。
  • Deployment 负责创建和替换 Pod。删除一个 Pod 后，副本控制器会补建。Service 用 selector 匹配 Pod 标签。本项目 Web selector 是 app: django-k8s-web，Service 端口 80 转发到容器 8001。
  • 如果 LoadBalancer 的 EXTERNAL-IP 一直 pending，检查负载均衡器。在本次排查中，K3s 配置禁用了 servicelb，Service 显示的 NodePort 仍可作为单独的排查入口。
  • kubectl create secret generic postgres-env --from-env-file=k8s/apps/db.env 在运行命令的电脑上读文件，先核对路径和当前目录。本项目 PostgreSQL 读取 postgres-env，Django 读取 django-k8s-web-prod-env。两边库名和凭据应对应。
  • 私有镜像用镜像拉取 Secret。本项目 Pod 指定 ghcr-pull，也可以把同命名空间的拉取 Secret 配到 default ServiceAccount，供新建 Pod 使用。Headlamp 的 viewer 服务账号读 Secret 返回 forbidden 属于 RBAC 权限限制。
  • CreateContainerConfigError 优先看引用的 Secret 或配置是否存在。ErrImagePull 和 ImagePullBackOff 用 kubectl describe pod <pod> 看 Events，区分标签不存在、权限、网络超时和拉取限速。镜像未启动时，kubectl exec 进不去。
  • ContainerCreating 可能在拉镜像，也可能在等挂载或网络。Terminating 是删除阶段。分别检查 Pod Events、节点和 K3s 日志，避免把所有等待都当成镜像慢。Error 或反复重启时优先看 kubectl logs <pod> --previous。滚动更新中旧 Pod 仍在 Running，不代表新版本已经上线。

5. GitHub Actions 和部署 Secrets

手动操作过集群后，我以教程 YAML 为底稿接入自动化。test-django.yml 负责测试，build.yml 串起测试、构建、推送、连接集群、更新 Secret、滚动发布、迁移和静态文件收集。

  • 测试工作流用 PostgreSQL 服务。Docker 的健康检查写 --health-timeout 5s 和 --health-retries 5。健康检查通过后，测试才能使用 PostgreSQL 服务。
  • GHCR 登录使用 GitHub 自动提供的 GITHUB_TOKEN，工作流需要 packages: write。如果已有 GHCR 包未继承仓库权限，还需要在 Package settings → Manage Actions access 给仓库写权限。登录成功而 push 返回 403 时，检查包级权限。
  • GitHub Settings → Secrets and variables → Actions 中配置 K3S_KUBECONFIG、DJANGO_SECRET_KEY、ENV_ALLOWED_HOST、POSTGRES_DB、POSTGRES_USER、POSTGRES_PASSWORD、POSTGRES_HOST、POSTGRES_PORT、DB_IGNORE_SSL。集群内数据库地址用 postgres:5432，站点域名可用 app.example.com 作占位示例。需要自动建立管理员时还可配置 DJANGO_SUPERUSER_USERNAME、DJANGO_SUPERUSER_PASSWORD、DJANGO_SUPERUSER_EMAIL。
  • 工作流把配置写到临时 .env.prod，再更新 K3s Secret。Pod 启动时读取环境变量，所以部署随后更新镜像。待 rollout 完成后执行迁移和 collectstatic。

6. 本次结束时的状态

  1. 第一轮 Actions 中，登录和构建成功，推送遇到 GHCR 403。配置包级写权限后，重跑已成功推送镜像。
  2. 重跑停在 Update deployment secrets。kubeconfig 里的 server 是 https://127.0.0.1:6443，GitHub Runner 连到的是自己的回环地址，返回 connection refused。后续 rollout 和迁移被跳过。
  3. 我接着验证 K3s API 的公网可达性。服务器的 ss -lntp 'sport = :6443' 显示 K3s 监听 *:6443。Windows 对实际 API 地址（下文用示例域名代替）进行测试，ping 有响应，但 TcpTestSucceeded : False。公网 TCP 尚未通过，证书校验尚未发生。
  4. 下次从服务器抓包开始。运行 tcpdump -ni any 'tcp port 6443'，同时从 Windows 重测。看不到 SYN 时检查绑定的安全组、入站端口和来源公网 IP。收到 SYN 却没有 SYN-ACK 时查服务器防火墙。收到并回应后客户端仍失败时查回程。
  5. TCP 打通后用 kubeconfig 副本测试 https://k3s.example.com:6443。K3s API 自带 HTTPS。若 x509 明确提示证书与 API 地址不匹配，检查 K3s 的 tls-san 配置。kubectl 验证通过后更新 GitHub Secret，并确认 GitHub Runner 的出口也在入站规则允许范围内。
